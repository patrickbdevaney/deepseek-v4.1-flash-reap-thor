## B1. BLOCKER: `Measure.__init__` calls `torch.zeros()` with no size, so s06 dies in its first layer unit

**Where:** `ops/s06_heal.py:60-63`

```python
z = lambda *s: torch.zeros(*s, dtype=torch.float64, device="cuda")
self.acc = {"replay_ratio": z(), "direct_ratio": z(), ...
```

**What happens.** `z()` expands to `torch.zeros(dtype=..., device=...)` with no size argument. Verified on CPU with the project venv (torch 2.14.1):

```
TypeError: zeros() missing 1 required positional arguments: "size"
```

`unit_layer` builds `Measure` before it calls `unit_layer_two_phase`, so `s06 unit layer --layer 0` exits non-zero. `orchestrate.run_unit` then raises, and the chain writes `chain.STOP "s06 heal failed"`. The failure is loud, but s06 cannot make progress.

`unit_layer_two_phase` has never executed, because s04 uses only the single-phase `unit_layer`. So this is the first code path that hits it. `lib/hooks.py:42` uses the same lambda but always passes sizes, so it is fine.

**Patch:**
```diff
--- ops/s06_heal.py
+++ ops/s06_heal.py
@@ -59,3 +59,3 @@
         self.m = torch.as_tensor(m_norm, dtype=torch.float32, device="cuda")
-        z = lambda *s: torch.zeros(*s, dtype=torch.float64, device="cuda")
+        z = lambda *s: torch.zeros(s, dtype=torch.float64, device="cuda")   # z() -> 0-d, z(n) -> [n]
         n = len(keep)
```

**Verified.** `torch.zeros(())` is 0-d, `torch.zeros((3,))` is `[3]`, and `torch.zeros((2, 5))` is `[2, 5]`. I also ran a CPU replica of `Measure` with this patch (`/tmp/claude-2002/audit-s10/m/run.py`: the class text with `cuda` replaced by `cpu`, a fake noaux gate with −inf pruned bias, 16 experts, top-3, 5 invalid tokens). It runs end to end under `torch.inference_mode()`. It also confirms that:
- the in-place updates of non-inference accumulators inside inference mode are fine;
- `finish()` writes every key that `finalize` and s07 read;
- `estimators()["replay"]` equals an independent numpy computation of `1 / mean_valid sqrt(e_post / e_pre)` (1.0574605 vs 1.0574605);
- `n_tok` sums to valid × top-k;
- invalid tokens are excluded;
- no pruned expert is selected post-prune.

There is no other crash in `Measure.__call__`, `estimators`, `decide` or `finalize` on that replica.

## C1. CORRUPT (gate is vacuous): the confirm split has no long-context row, so `max_long_bin_top1_drop` can never fire on the release panel

**Where:** data plus `ops/lib/gates.py:273-289` (`pruned_floor`) and `ops/lib/rowsets.py:29-41`

**Evidence** (real corpus, `spec_hash c1803e70af7db162`):
- There are 55 held-out rows. Only **one** is `longctx`: row 506, 58 789 tokens. `split_of` puts it in **screen**.
- The confirm split is 26 rows and 212 992 tokens. Every row is 8 192 tokens: agentic 5, code 3, finance 3, general 4, math **1**, multilingual 3, science 3, vision 4.
- The scored-token position bins on the final panel (computed with `metrics.row_frame`) are `[0,8)` … `[4k,8k)` only. Every bin from `[8k,16k)` up is **empty**.

**What happens.** `pruned_floor` skips missing bins and appends the note "long-context retention UNTESTED", then returns `pass=True`. So the mxfp4_master, nvfp4, thorA and b128 release gates all pass their long-context clause by default. The pre-registered vision-and-long-context protection (GLM ballast lesson) is not enforced for release.

Two related effects:
- `--tokens 393216` buys nothing: the whole confirm split is only 213k tokens.
- Bucket `math` is a single document (8 191 scored tokens). It is not `under_sampled` (min 2000 tokens), so `min_bucket_top1` for math rests on one cluster.

**Patch.** It must go in **before** the first s10 result, because the prereg lock is written at the start of `s10 heal`. Fail closed when a pre-registered long-bin check is untestable, and record the reason. Do not let it pass silently.

```diff
--- ops/lib/gates.py
+++ ops/lib/gates.py
@@ -288,3 +288,6 @@
     notes = [] if long_checked else ["no adequately sampled bin past 8k: long-context retention UNTESTED"]
+    if not long_checked and f.get("long_bins_required", True):
+        why.append("long-context retention untestable on this split (no adequately sampled bin >= "
+                   f"{f['long_bins_from']}); pre-registered gate cannot be evaluated")
     return {"pass": not why, "why": why, "notes": notes, "long_bins_checked": long_checked}
```

That alone would block every release on this corpus. The real fix is a data or pre-registration decision for the user. Options:
- (a) Add `"long_bins_required": false` to `s10_gates.json` now, as an explicit, pre-registered acknowledgement that the long-context check is screen-only. Then also score the screen longctx row in the heal panel and report it on the cards as a non-release diagnostic.
- (b) Re-split held-out `longctx` by bucket so that each half gets at least one row. This would change the screen rows s04 already used, so it is not viable mid-run.
- (c) Build extra held-out longctx rows for confirm only.

**Uncertain:** whether the user prefers (a) or (c). The code as written passes silently, which is the defect.

## R2. RISK: non-finite student metrics are dropped silently, so a partly broken arm scores better

**Where:** `ops/lib/stats.py:138-139` and `155`, `ops/lib/metrics.py:56-62`

`cluster_bootstrap_mean` and `paired_diff` keep only finite values and do not count what they drop. Take a Thor or overlay arm whose dequant produces NaN or inf logits on some rows, for example a bad fp16 KT scale or an overflow. Its `kl32` and `dnll` on those tokens disappear from the means and from the paired differences. So `thor_quant`, overlay and the A/B decision are computed on a favourable subset.

The point checks also fail open on NaN. `pruned_floor` uses `x > max`, `thor_quant` uses `d > max` and `overlay` uses `hi > max`, and all of these are False on NaN. Only `control` uses `not <=`.

Teacher-side NaN cannot occur on scored tokens: I checked every scored token on both panels and the teacher NLL is finite everywhere.

```diff
--- ops/lib/metrics.py
+++ ops/lib/metrics.py
@@ -56,6 +56,10 @@
         m = np.load(Path(run_root) / arm / "metrics" / f"r{r:05d}.npz")
         s = f["scored"]
+        bad = ~np.isfinite(m["kl32"][s]) | ~np.isfinite(m["nll"][s])
+        if bad.any():
+            raise SystemExit(f"{arm} row {r}: {int(bad.sum())} scored tokens have non-finite kl32/nll "
+                             "(broken arm numerics); refusing to score it")
         cols["kl32"].append(m["kl32"][s].astype(np.float64))
```

## R4. RISK: the s06 calibration subset is 10 rows (one per bucket), which leaves thin coverage for the s07 NVFP4 input scales and the imatrix

**Where:** `ops/s06_heal.py:181-183` (`--tokens 131072`)

`rowsets.subset(calib, 131072)` returns 10 rows and 106 496 tokens:
- rows 0-8: one 8 192-token row per bucket;
- row 351: 32 768-token longctx.

I used `hope_sum_knee` as a proxy keep-set and the s03 teacher routing on those rows to estimate coverage:
- The minimum number of tokens per kept expert is 40 at L0, 76 at L10, 21 at L20 and **0** at L39.
- At L39, 6 experts get fewer than 32 tokens.

Post-prune routing adds tokens, so this is a lower bound. The gain itself is a single scalar and is fine at this size. But the s07 `input_scale = amax / 2688` and the imatrix for those experts rest on a handful of tokens, or on the s03 fallback.

Suggestion: raise `--tokens` in `chain.sh`'s s06 call, for example to 393216. Phase A is idempotent per layer, so the cost is runtime only. Not a code defect.

## R6. RISK: disk batching never refuses

**Where:** `ops/lib/orchestrate.py:185-190` and `s10_eval.py:106`

`k = max(1, (free - margin) // per)` gives k = 1 even when `free < margin`, so a panel proceeds and can hit ENOSPC mid-layer. That failure is loud and resumable, but the panel loses time. On the final panel, `bytes_per_arm(212992) = 8.7 GB` per arm, plus `_embed` and `state/`. Today's disk has 99 GB free, while s04's replay holds 104 GB, and the Thor A192 build (~100 GiB) lands before s10 final. Suggest refusing when `free - margin < per`:

```diff
-    k = max(1, (free - margin) // max(per_item, 1))
+    k = (free - margin) // max(per_item, 1)
+    if k < 1:
+        raise SystemExit(f"disk: {free / 2**30:.0f} GiB free < margin {margin / 2**30:.0f} GiB + one arm "
+                         f"{per_item / 2**30:.1f} GiB")
```

Note that s04 shares this helper. Apply it after s04 finishes.

## R7. RISK: one sha covers the whole of `s10_gates.json`, including the `s11` / `gguf` sections

## Checked and found correct

**Real-file key/shape/dtype contract.** I read everything with `np.load(mmap_mode='r')` or json, never loading a large array whole.
- `s03/bank/L*.npz` has `nrm` and `cnt` as `[9, 384]` f64. `nrm` is the **sum of ungated ‖f‖** (hooks.py:173), so `nrm.sum(0) / cnt.sum(0)` is the mean ‖f‖ the README formula needs. It is not the Super-Expert max, which is `fmax`. The bank also has `amax_in`, `amax_mid`, `x2_in [384, 5120]`, `x2_mid [384, 2304]` and `n_tok`.
- `s03/teacher`:
  - `top32_ids` int32 `[4975198, 32]`;
  - `top32_logprob` f32 `[4975198, 32]`;
  - `nll_next` f32 `[4975198]`.
- `s03/routing/L*_idx` is u16 `[T, 6]` and `L*_w` is f16 `[T, 6]`.
- `corpus`:
  - `tokens` is u32, `types` is i8 (values −1 and image ids ≥ 0), `valid` is u8;
  - `rows.jsonl` has row, bucket, offset, length, heldout, images and n_valid;
  - `manifest.json` has spec_hash and `max_row_len = 65536`.
- Config:
  - dim 5120, moe_inter_dim 2304, 40 layers, 384 experts, top-6, hc_mult 4;
  - `bytes_per_arm`'s hard-coded 5120 is correct.

**Split discipline.**
- s04, s10 heal and s10 final all use `rowsets.split_rows` and `subset` with the same spec hash and `TOKEN_TARGET`.
- The recomputed screen subset (18 rows, 198 053 tokens) is **identical** to `s04/replay/run.json` rows, so the s10 heal panel uses exactly the s04 arbitration rows.
- The confirm subset (all 26 confirm rows) is disjoint from screen.
- s06 and s07 use `calib` (`heldout == false`), which is disjoint from all held-out rows.
- drift_guard `check` uses `--rows calib`.
- The s03 bank, which feeds s06's `m`, excludes held-out rows.

**Heal formula and adoption rule.**
- `e = Σ w² m²` and `gain = 1 / mean_valid √(e_post / e_pre)` match README §s06 (numerically verified above).
- The gain multiplies only the routed sum (`install_arm_moe`), the same way in s06 phase B, the s10 `healed`/`healed_A` arms, the s07 w2 fold and the NVFP4 global scale.
- `gates.heal` implements `d_kl32 hi < 0 AND McNemar z > −1.96` on `compare(healed, unhealed)`, exactly as `s10_gates.json` `heal.adopt_if` says.

**Statistics, tested with synthetic data** (`/tmp/claude-2002/audit-s10/stat_test.py`, 26 clusters of 100 tokens):
- `paired_diff(a, b)` is negative when a is lower, with `excludes_zero` correct.
- `mcnemar(a, b).z > 0` when a agrees more.
- `heal` adopts when healed is better and rejects when it is worse.
- `arm_decision` returns A when thorA is better and B when it is worse.
- The overlay gate direction is correct.
- `cluster_bootstrap_mean` is ratio-of-sums.
- MCS eliminates the clearly worse arm and keeps two near-equal arms.
- `pruned_floor` must-beat-random uses `hi < 0` on `arm − random`.
- The long-bin drop is `ref − bin > max`.
- `thor_quant` uses mean `d(thorA − healed/mxfp4) > 0.25`.
- `trellis` uses `hi < 0`, `z > 0`, bytes ≤ and the gemv ratio ≤ 1.10, with a missing bench meaning not adopted.

**Scoring.**
- `scored` excludes the last token, pad (valid = 0) and positions whose next token is an image token.
- `t_top1 = top32_ids[:, 0]` is the teacher argmax.
- kl32 is GLM `topk_KL`.
- The head path, `hc_pre` with the last `ffn_pre`, then norm, then head, matches the reference `Transformer.forward`.
- Teacher NLL is finite on every scored token of both panels.

**Resume behaviour.**
- s06 phase A is idempotent: the accumulators restart, and every row is recomputed after a mid-phase-A crash.
- The `measure/L*.npz` file is persisted before the `phaseA` ledger mark.
- Phase B reloads the gain deterministically from that file.
- Journals make row application crash-safe.
- `finalize` is re-runnable.
- s10 panels resume per (arm, layer, row) and per (arm, head, row). Batches are recomputed from the ledger.
- `analyse` is deterministic (fixed seeds), so a re-run after a crash between `results.json` and `gates.json` reproduces the same decision.
- The prereg lock is created at the first s10 call and checked at every later one.
