## Checked and found correct

- **decide vs. replay format.** decide reads exactly what `replay.unit_head` writes: `replay/<arm>/metrics/r%05d.npz`
  holding `kl32` f32, `top1` i32 and `nll` f32, length = row length. `run.json` holds `rows` (18 screen rows) and `arms`
  (control + 11, in the same order as candidates.json). Row ids are < 100000 (552 rows), so the `%05d` names are safe.
- **decide vs. real inputs.** `metrics.row_frame` runs on the real corpus and teacher: `rows.jsonl` index == `row` for all
  552 rows; teacher `top32_ids` int32 and `top32_logprob` f32 are [4975198, 32]; `nll_next` f32 [4975198]; corpus types int8,
  valid uint8. No NaN teacher NLL on any scored position; ids are in vocab; log-probs are sorted descending.
- **Gates and statistics.** `s10_gates.json` has `control.max_kl32/min_top1` and
  `arbitration.ineligible_drift_verdicts`. The control gate fails correctly on NaN. Everything in the decide output is
  JSON-serialisable.
- **Masks and keep-set fingerprints.**
  - All 11 `masks/*.json` load with matching stored and content sha. All are 40 layers × n_keep (192 or 128), ids in
    [0, 384).
  - `*.keep.json` fingerprints match. `run.json` keep_sha256 matches candidates.json sha256.
  - Eligibility: the randoms are ineligible; every other candidate is FLAT, so none is drift-blocked.
- **Keep-set fingerprint end to end.**
  - `keepset.save` lets the `n_keep=` meta override the list form harmlessly.
  - keepset.json → s05 ledger, `reap_keepset.json` and `manifest.keepset_sha256` are all the same canonical fp (checked in
    the synthetic run).
  - s05 ledger re-run with a different keep-set raises KeepsetMismatch (a SystemExit subclass).
- **Real checkpoint layout.**
  - Shard i (3..42) holds exactly decoder layer i−3, and nothing else.
  - Each layer has 384 experts × w1/w2/w3 × {weight I8 [2304,2560]/[5120,1152], scale F8_E8M0 [2304,160]/[5120,72]}.
  - `ffn.gate.weight` BF16 [384,5120]; `gate.bias` and `gate.bias_vl` F32 [384].
  - No `.experts.` name escapes the EXPERT regex (so no pruned expert can leak through the verbatim branch). No hash-routing
    tensors. No 0-d tensors.
  - The source has no `__metadata__`.
  - All dtypes (F8_E8M0, I8, BF16, F32, F8_E4M3) are in `st_io.DT`.
- **MTP/DSpark and Engram tensors.**
  - `mtp.*` (shards 44-46, 128 experts, own gate [128]) is copied verbatim. `config.text_config.dspark_n_routed_experts=128`
    and inference `dspark_n_routed_experts=128` are untouched, and `model.py:get_moe_config` uses them for MTP. Setting

  - Every small file in `$V41_SRC` matches the pinned tree (git blob sha1 / lfs sha256). Nothing is locally modified, so the
