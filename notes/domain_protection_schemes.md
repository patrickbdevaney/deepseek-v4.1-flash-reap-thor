# Per-domain expert protection / coverage schemes for MoE pruning (GEC, MESA, union guard, PreMoe, EASY-EP) and how they compose with REAP/HOPE

Scope: selection-side schemes that reserve, cover or protect experts per domain/corpus/language so that pruning past 50% does not collapse minority capabilities; how they compose with REAP saliency and HOPE's p^T F p objective; how the protection budget should scale with the total prune ratio. Internal context: GLM-5.3-Flash 288 routed experts, 7 calibration domains, scalar `protect_frac = 0.04`, v2 run with `protect_frac = 0` lost general-text ballast. Internal measurements are cited to the local memory notes. All arXiv IDs are 2025–2026 unless stated. Model scale is given for every result.

## KQ1. Generic TB-Coverage (arXiv 2607.01710): exact mechanism, numbers, ablations

### Takeaway
GEC is a protect-then-fill rule: REAP-style per-expert scores are computed separately on WikiText2 and C4, a fixed per-layer budget B (20 of 60 experts for Qwen1.5-MoE-A2.7B, 24 of 64 for DeepSeek-MoE-16B) is filled round-robin from the two per-corpus rankings, merged into a C4 reconstruction mask, and the lowest-average-score unprotected experts are trimmed to K. It beats REAP by +4.6 (Qwen) and +6.4 (DeepSeek) points on a six-task zero-shot average at 50% retention, but there is no protection-budget ablation, no pooled-score ablation, nothing below 25% retention, and the models are small (2.7B/16B, 60–64 experts); its MMLU is actually below REAP's at 50%.

### Cited Findings
- Paper: "Generic Expert Coverage for Pruning Sparse Mixture-of-Experts Language Models", Zeng, Pan, Wang, Zheng, Kim, Ma, Zhou; submitted 2 July 2026; 6 pages; no code repository found (SOTAVerified lists it as unverified with no reproductions). — [arXiv 2607.01710](https://arxiv.org/abs/2607.01710); [sotaverified](https://sotaverified.org/papers/260701710)
- Per-corpus utility (Eq. 2) is REAP-style: s_t^(l)(e) = E[ g_e(x) · ||f_e(h_x^(l))||_2 | e ∈ TopK(x) ], averaged only over tokens of corpus t for which e is in the top-k; "We profile each calibration corpus independently, producing a separate score vector ... per MoE layer." — [arXiv 2607.01710 §3](https://arxiv.org/html/2607.01710)
- "Coverage" has no formal definition; the paper states it "does not ... optimize a formal diversity objective". Coverage is operationalised solely by the round-robin protection rule. — [arXiv 2607.01710 Limitations](https://arxiv.org/html/2607.01710)
- Protection rule (verbatim steps): sort experts by s_WikiText2 → π_Wiki; sort by s_C4 → π_C4; "Starting with an empty protected set P_l, alternate between the two rankings: at each step, take the highest-ranked expert from the current corpus's ranking that is not yet in P_l, and add it. Stop when |P_l| = B." "An expert that is top-ranked on WikiText2 but mid-ranked on C4 will still be protected, even though its average score might not place it in the top-K by a single-criterion ranking. If both rankings agree on the top experts (high overlap), the round-robin degenerates to standard top-B selection, so the rule introduces no harm in that case." — [arXiv 2607.01710 §3](https://arxiv.org/html/2607.01710)
- Mask construction: "We initialize from a reconstruction-stable candidate mask m̂_l (obtained via layerwise reconstruction minimization on C4) that already retains K experts per layer. We merge the protected set P_l into this candidate: set m_l(e)=1 for all e ∈ P_l ..., then if the union exceeds K, remove the lowest-ranked unprotected experts in order of ascending average score s̄^(l)(e) until exactly K experts remain. Protected experts are never removed; the budget is restored entirely by dropping unprotected reconstruction-selected experts." — [arXiv 2607.01710 §3](https://arxiv.org/html/2607.01710)
- Budget: B is "a per-layer protection budget ... chosen such that B ≤ K for every layer and retention budget, guaranteeing feasibility"; the experiments "use fixed protection budgets (20 experts for Qwen, 24 for DeepSeek) across all retain ratios. These values were selected to provide sufficient coverage without dominating the mask at high retain ratios. Sensitivity analysis of the protection budget is an important direction for future work." — [arXiv 2607.01710 Discussion](https://arxiv.org/html/2607.01710)
- Internal inconsistency: at 25% retention K = 15 (Qwen, 60 experts, top-4) and K = 16 (DeepSeek, 64 experts, top-6), so B = 20/24 exceeds K, violating the stated B ≤ K condition; the paper does not say whether B is clipped or whether the protected set alone fills the mask at 25%. — [arXiv 2607.01710 §4 Setup](https://arxiv.org/html/2607.01710)
- Calibration: "512 sequences of length 1024 tokens from each corpus" (WikiText2, C4), two forward-only profiling passes; "No downstream benchmark data is used". REAP baseline was run with Evol-CodeAlpaca calibration (128 texts, seq len 2048), i.e. the REAP comparison is generic-corpus GEC vs code-calibrated REAP, not a pooled-vs-per-corpus comparison on the same data. — [arXiv 2607.01710 §4](https://arxiv.org/html/2607.01710)
- Benchmarks: Common Avg = unweighted mean of ARC-Challenge, ARC-Easy, HellaSwag, PIQA, WinoGrande, BoolQ (zero-shot); auxiliary MMLU, GSM8K, Math500; WikiText2/C4 PPL. Random is mean±std over 6 seeds. — [arXiv 2607.01710 §4](https://arxiv.org/html/2607.01710)
- Qwen1.5-MoE-A2.7B results (Avg / MMLU / W.PPL / C.PPL): 25% ret — Random 0.417 / 0.240 / 920.67 / 3109.75; REAP 0.438 / 0.247 / 193.65 / 551.91; ExpertSparsity 0.407 / 0.233 / 160.93 / 358.90; GEC 0.448 / 0.234 / 146.22 / 259.12. 50% ret — Random 0.535 / 0.315 / 77.95 / 165.33; REAP 0.552 / 0.406 / 23.77 / 61.47; ExpertSparsity 0.519 / 0.325 / 36.18 / 88.31; GEC 0.598 / 0.369 / 16.76 / 47.01. 75% ret — Random 0.645 / 0.516 / 13.25 / 33.80; REAP 0.629 / 0.519 / 13.78 / 32.81; ExpertSparsity 0.655 / 0.548 / 11.92 / 29.41; GEC 0.662 / 0.528 / 10.57 / 28.22. — [arXiv 2607.01710 Table 1](https://arxiv.org/html/2607.01710)
- DeepSeek-MoE-16B-Base results (Avg / MMLU / W.PPL / C.PPL): 25% ret — Random 0.403 / 0.243 / 728.88 / 2640.77; REAP 0.395 / 0.238 / 544.15 / 1734.92; ExpertSparsity 0.404 / 0.240 / 176.63 / 615.18; GEC 0.448 / 0.232 / 137.03 / 423.72. 50% ret — Random 0.488 / 0.244 / 54.19 / 249.73; REAP 0.542 / 0.287 / 27.33 / 61.60; ExpertSparsity 0.571 / 0.264 / 20.88 / 53.47; GEC 0.606 / 0.242 / 16.43 / 45.14. 75% ret — Random 0.568 / 0.260 / 19.19 / 80.94; REAP 0.649 / 0.340 / 14.08 / 29.94; ExpertSparsity 0.678 / 0.314 / 12.17 / 27.70; GEC 0.683 / 0.309 / 10.12 / 25.96. — [arXiv 2607.01710 Table 1](https://arxiv.org/html/2607.01710)
- The "+4.6 to +6.4 points over REAP at 50% retention" is therefore Qwen 0.598−0.552 = +0.046 and DeepSeek 0.606−0.542 = +0.064 on Common Avg; vs ExpertSparsity the paper states +0.041/+0.080/+0.007 (Qwen 25/50/75%) and +0.044/+0.035/+0.006 (DeepSeek). — [arXiv 2607.01710 Table 1](https://arxiv.org/html/2607.01710)
- MMLU is NOT improved by GEC: at 50% retention REAP beats GEC on MMLU on both models (Qwen 0.406 vs 0.369; DeepSeek 0.287 vs 0.242); at DeepSeek 25% GEC's MMLU (0.232) is the lowest of all methods. GSM8K/Math500 are ~0 for every method ("we cannot assess the method's effect on reasoning ability"). — [arXiv 2607.01710 Table 1, Limitations](https://arxiv.org/html/2607.01710)
- Authors' explanation for ratio dependence: "The improvement from Generic TB-Coverage is largest at 25% and 50% retain, where retaining the right experts is critical. At 75% retain, most experts are preserved and the gap between methods narrows ... coverage-aware selection is most valuable when the pruning budget is tight." PPL at 25% retain is reduced "by 9%–24% (Wiki) and C4 PPL by 28%–39% over the next-best method". — [arXiv 2607.01710 Discussion](https://arxiv.org/html/2607.01710)
- Ablations present: only multi-seed random analysis (single seed 42 at Qwen 75% gives 0.669 > GEC 0.662 but 6-seed mean 0.645±0.041, worst seed 0.604). Ablations absent: protection budget B, corpus choice, overlap between the two protected rankings, pooled/mean/max aggregation baseline ("we leave this systematic ablation to future work"). — [arXiv 2607.01710](https://arxiv.org/html/2607.01710)
- Limitations (verbatim excerpts): "intentionally simple and static: it does not adapt experts after pruning, learn corpus weights, or optimize a formal diversity objective ... only two generic corpora and two open-base MoE models of moderate scale (2.7B and 16B parameters); whether the same coverage rule scales to instruction-tuned models, larger expert counts, or pruning-plus-quantization settings remains open ... The protection budget B is fixed across retain ratios and requires manual selection." — [arXiv 2607.01710 Limitations](https://arxiv.org/html/2607.01710)

### Inferences
- Protected fraction of the mask, computed from the paper's numbers (my arithmetic): Qwen B/K = 20/45 = 44% at 75% retention, 20/30 = 67% at 50%, 20/15 = 133% at 25%; DeepSeek 24/48 = 50%, 24/32 = 75%, 24/16 = 150%. Because B is fixed while K shrinks, protection silently grows to dominate and then exceed the mask as the ratio rises; at 25% retention the "coverage" mask is, by construction, nothing but the round-robin of the two per-corpus top lists, and the C4 reconstruction candidate contributes nothing. The 25%-retention gains are therefore evidence for "top-B union of per-corpus REAP rankings" beating C4-reconstruction and code-calibrated REAP on generic text, not evidence for a tuned protection/fill balance.
- Because each corpus contributes at least ⌈B/2⌉ unique experts when rankings are disjoint, and fewer unique experts when they overlap, the effective per-corpus reservation is 10–12 experts per layer (17–19% of the layer) on 60/64-expert models. Scaling this to a 288-expert layer by fraction gives ~48–54 reserved experts per corpus, far above our 0.04×288 ≈ 11.5; scaling by count gives ~10–12, matching ours. Which scaling is right is not identifiable from the paper (no budget ablation, no fine-grained-MoE model).
- The REAP-vs-GEC comparison confounds calibration corpus (code vs generic) with mechanism, which is why MMLU can go down while ARC/HellaSwag/PIQA go up: GEC's generic protection improves commonsense/PPL (the WikiText2/C4-like capability), not knowledge recall. For our ballast problem this is a warning: generic-corpus protection preserved the "generic" ballast as measured by PPL and commonsense, but did not preserve MMLU-type recall.

### Gaps
- No sensitivity analysis of B anywhere (confirmed by the authors' own Limitations), so "how much protection" is unmeasured.
- No pooled-score vs per-corpus comparison on identical calibration data; the +4.6/+6.4 is partly a calibration-corpus effect.
- Nothing on models with 128–288 experts, instruction-tuned models, or ratios below 25% retention; no code released.
- How B > K is handled at 25% retention is undocumented.

## KQ2. Other protection / coverage / reservation methods (MESA minimax, union guard, PreMoe generalist, EASY-EP mixed, language-specific, 2610.15578, 2606.18304, 2606.03328)

### Takeaway
Besides GEC, the published protection-style mechanisms are: MESA's minimax over per-domain routing-mass loss (greedy score boosting; worst domain +18 pt vs REAP on gpt-oss-20b at 25% pruning but AIME −13 pt and it fails on standard-routing Mixtral); Half-the-Experts' "union guard" of top general-traffic experts (HumanEval+ 0.817→0.829 at 25% keep on Qwen3.6-35B, no general-text number); PreMoe's equal-weight domain-averaged utility (generalist loses far more than specialists at 75% pruning); and EASY-EP's per-domain normalised-then-averaged scores (mixed-domain R1 at 50% keeps 91.5% of full average but FinanceIQ falls 82.1→57.95). None of them formulate a coverage constraint over an interaction objective, and none report the protection budget as a function of ratio.

### Cited Findings
- MESA ("When Load-Balancing Goes Too Far", arXiv 2609.04453, NeurIPS 2026): objective = choose the prune set minimising the maximum over domains of the fraction of that domain's total router mass that lies in the pruned set (Eq. 2); solver = greedy heuristic (Algorithm 1) that ranks experts globally, finds the domain with highest loss, boosts that domain's scores by a decaying step (η0 = 0.15, T = 20), re-normalises and keeps the best solution; "no formal convergence guarantee". Scores are router mass only; it is not combined with REAP activation norms. — [arXiv 2609.04453](https://arxiv.org/html/2609.04453)
- MESA over-dispersion diagnostic: mean per-token router entropy > ~0.85·log2(E) ("soft guideline"); gpt-oss-20b = 90.8% of max entropy, Mixtral-8x7B-Instruct = 74.3%. Models: gpt-oss-20b (32 experts, top-4), Mixtral-8x7B-Instruct (8, top-2), OLMoE-1B-7B (64, top-8), Gemma-4-26B-A4B-it (128, top-8, not over-dispersed), gpt-oss-120B (128). Six calibration domains: math, coding, commonsense, science, instruction following, general knowledge. Main ratio 25% pruned; OLMoE swept 25/37.5/50%; gpt-oss-120B at 50%. — [arXiv 2609.04453](https://arxiv.org/html/2609.04453)
- MESA results, gpt-oss-20b, r = 0.25: worst domain GPQA-Diamond baseline 64.47 → MESA 65.48 (+1.0), REAP 47.72 (−16.75), RM-Uniform 56.85 (−7.62); cost on best domain: AIME'25 MESA −13.34 vs REAP −3.34; GSM8K MESA +4.01; MESA beats REAP on 7/11 benchmarks. ### Inferences
- The field has three distinct protection mechanisms: (a) hard reservation of top-B per corpus/domain (GEC, union guard — our `protect_frac` is this type); (b) minimax over per-domain mass loss (MESA — a soft, iterative version of (a) that also decides which domain gets protected next); (c) score renormalisation/averaging across domains (PreMoe 1/D weights, EASY-EP per-domain normalisation — rebalancing, not reservation). Only (a) guarantees a floor per domain regardless of mix; (c) is equivalent to corpus rebalancing and our audit already showed rebalancing alone cannot recover ballast information that calibration never collected.
- MESA's Mixtral failure (standard routing) and 50% "mixed" result say minimax protection is beneficial exactly in the over-dispersed regime; its own threshold (0.85·log2 E ≈ 6.9 bits for 288 experts) is the cheap diagnostic to run on GLM-5.3-Flash's banked router stats before deciding how hard to protect.
- The PreMoe generalist collapse at 75% (LCB 20.22 vs specialist 49.63) and EASY-EP's mixed FinanceIQ −24 pts at 50% show that averaged/rebalanced domain scores do not protect thin domains at high ratios; hard reservation is the only published type with a floor, and GEC is the only one with a positive result at 75% pruned (on 60/64-expert models).

### Gaps
- No paper tests hard per-domain reservation with more than two corpora on a 128–288-expert model at ≥60% pruning.
- Half-the-Experts never states the guard size or the guard's effect on general-chat PPL; MESA never reports a budget.
- No language-protection result reports non-translation capability.

## KQ3. Protection budget vs total prune ratio: how many experts per domain are load-bearing, overlap, and feasibility at 60–70%

### Takeaway
Published overlap statistics (PreMoe 28–42% at top-16, 4–16% at top-2, 80–86% at top-128; MESA 41–47% top-8; translation IoU ~0.6 at 75% pruned) say the per-domain "core" is small and largely disjoint while the broad per-domain set is mostly shared, so a reservation of ~10–20 experts/domain over 7 domains stays well under the 86–115 experts kept at 60–70% of 288 after de-duplication; but GEC's fixed B already consumes 67–75% of the mask at 50% retention and exceeds it at 25%, and no paper measures whether protection should grow, shrink, or stay fixed in count as the ratio rises.

### Cited Findings
- GEC: B fixed at 20/60 and 24/64 "across all retain ratios", "selected to provide sufficient coverage without dominating the mask at high retain ratios"; K = 45/30/15 (Qwen) and 48/32/16 (DeepSeek). — [arXiv 2607.01710](https://arxiv.org/html/2607.01710)
- EASY-EP: "25 demonstrations are sufficient to capture all domain-specific experts (99%)" (from the gating-score analysis, Section 3.2, baseline for the 99% undefined); top-16 experts "largely disjoint" across domains; at top-128 overlap rises but "a significant portion of the experts remains domain-specific"; math-internal overlap >84%. — [arXiv 2504.06792](https://arxiv.org/html/2504.06792)
- PreMoe (DeepSeek-R1): cross-domain overlap of top experts ~80–86% at top-128, 28–42% at top-16, 4–16% at top-2; 5–10 calibration samples per domain recover most accuracy; no minimum expert count per domain given. — [arXiv 2505.17639](https://arxiv.org/html/2505.17639)
- MESA: top-8 overlap between domains ≈ 41–47% (gpt-oss-20b, 32 experts). — [arXiv 2609.04453](https://arxiv.org/html/2609.04453)
- Translation: IoU of pruned sets between languages at k = 24 of 32 "consistently around 0.6". — [arXiv 2605.28042v2](https://arxiv.org/html/2605.28042v2)
- Internal: GLM-5.3-Flash REAP50 bucket-resolved retained saliency mass: general 0.4865 vs agentic 0.7466, code 0.7283, math 0.7133, science 0.7204; general is 4.76% of calibration routed tokens; bucket-balanced re-mask recovers only +0.028. — [memory: reap-criterion-and-corpus-audit](/home/patrickd/.claude/projects/-home-patrickd/memory/reap-criterion-and-corpus-audit.md)
- Internal: exact min-plus DP non-uniform allocation gain shrinks with ratio (−4.98% at 50%, −3.83% at 65%, −3.24% at 75%) but is unshippable (single scalar `num_local_experts`). — [memory: reap-criterion-and-corpus-audit](/home/patrickd/.claude/projects/-home-patrickd/memory/reap-criterion-and-corpus-audit.md)

### Inferences
- Arithmetic for our setting (extrapolation, my numbers): `protect_frac = 0.04` × 288 ≈ 11.5 experts per domain per layer; 7 domains → ≤ 81 experts if disjoint (28% of 288). Mask sizes: 144 at 50%, 115 at 60%, 86 at 70%. Using PreMoe's top-16 overlap (28–42%) as the proxy for top-12 overlap, the de-duplicated union is roughly 50–60 experts, i.e. ~35–42% of the mask at 50%, ~45–52% at 60%, ~60–70% at 70%. So at 70% the protected union approaches GEC's 67–75% protected share at 50% retention. It is feasible, but the free (saliency/HOPE-chosen) slice shrinks to ~25–35 experts per layer at 70%, which is where the interaction objective has to do its work.
- "Should protection grow with ratio?" — no measurement exists. Two published data points point opposite ways: GEC (fixed count ⇒ protected *fraction* grows and the method still wins most at 25% retention) and PreMoe/EASY-EP (domain cores are ~top-16 of 256, i.e. the load-bearing set is small, so a fixed count ~12–16 should suffice). The safe reading is: keep the *count* per domain fixed at the knee you measured (≈12), let the fraction grow, and accept that at 70% the free slice is ≤ 1/3 of the mask. Protection "eats the ratio" only in the sense that the free slice vanishes; it never makes the ratio infeasible as long as 7 × count × (1 − overlap) < K, which holds for count ≤ 20 at 70% on 288 experts.
- The 25-demonstration result is about calibration *samples*, not expert count; it says the per-domain expert ranking saturates fast, which supports a small per-domain slice but says nothing about how many of those experts must be kept.

### Gaps
- No published measurement of worst-domain retention vs protected count per domain at any ratio ≥ 60%; GEC explicitly defers it, MESA gives none, Half-the-Experts gives none. The `protect_frac` knee at 0.04 is the only datapoint for our shape and it was measured at 50%.
- No overlap statistics for a 288-expert, 7-domain, noaux_tc-sigmoid router; PreMoe/EASY-EP numbers are DeepSeek-R1 (256 experts, sigmoid) and are the closest proxy.

## KQ4. Interaction with HOPE (p^T F p): do protected experts conflict with the interaction objective, and is there a coverage-constrained formulation?

### Takeaway
No published method optimises an interaction objective subject to per-domain coverage constraints; HOPE's paper has no protection, domain balancing or constrained variant (only shared experts are never pruned), and MESA composes protection only with router-mass scores, not with activation-norm or pairwise terms. Mathematically, fixing protected experts as p_e = 0 is a linear constraint on HOPE's binary QP and reduces it to the same QP over the unprotected pool, so it composes cleanly — but that composition is an inference, not a measured result.

### Cited Findings
- HOPE objective: choose prune set P minimising p^T F p with p ∈ {0,1}^E, Σp = |P|; F_ij = conditional average over tokens where both i and j are in the top-K of g_i g_j ||f_i|| ||f_j||; diagonal reproduces REAP-style scores; solved by continuous QP relaxation and rounding ("empirically tight"); no greedy. — [arXiv 2609.18916](https://arxiv.org/html/2609.18916)
- HOPE calibration: Evol-CodeAlpaca-v1 (coding) and SWE-Bench-verified trajectories (agentic), used separately; "The paper does not discuss domain balancing, per-domain protection, or reserved experts"; "Constrained variants with fixed or protected experts are not discussed ... shared experts (in GLM-4.5-Air) are never pruned". Models: Qwen3.5-122B-A10B (256 experts, top-8, 48 MoE layers), Qwen3.5-35B-A3B, GLM-4.5-Air (128 experts); ratios 10–50%, nothing above 50%. — [arXiv 2609.18916](https://arxiv.org/html/2609.18916)
- HOPE results: 40–50% average rank 1.58 vs REAP 2.42; overall rank 2.07, top-1 in 39% of conditions vs 15% for REAP; agentic gains up to +6.1%; mixed per-table (e.g. 50% Evol-CA on Qwen3.5-122B Tulu mean 43.75 vs REAP 40.18; GLM-4.5-Air on SWE-Bench-verified calibration REAP 43.41 vs HOPE 40.90); "HOPE's advantage is smaller on simple recall tasks such as PopQA"; at 50% several baselines (esp. Freq) collapse. Limitations: ~6–7% slower calibration, F needs more data (10k vs 8k prompts to 99% prune-set agreement), per-layer independent, pairwise only. — [arXiv 2609.18916](https://arxiv.org/html/2609.18916)
- Internal: HOPE's F matrix accumulation implemented (`~/glm-5.3-reap/scripts/hope_fmatrix.py`); 47 MiB for 47 layers × 256 experts; projected gradient alone hit the optimum on only 27/40 random 8×8 problems, greedy 1-swap refinement fixed it to 40/40. — [memory: hope-supersedes-reap](/home/patrickd/.claude/projects/-home-patrickd/memory/hope-supersedes-reap.md)
- Internal (sibling note): at 50% with code-only calibration, REAP's MMLU fell to 20.87 and PopQA to 1.68 in HOPE's tables; HOPE's own MMLU loss at 50% on Qwen3.5-35B shows "the quadratic objective can sacrifice a minority domain not represented in calibration". — [sibling note: expert_pruning_beyond_50.md](/home/patrickd/glm-5.3-reap/research_notes/Compressing%201T%20MoE%20for%20Thor/expert_pruning_beyond_50.md); [sibling note: calibration_and_evaluation.md](/home/patrickd/glm-5.3-reap/research_notes/Compressing%201T%20MoE%20for%20Thor/calibration_and_evaluation.md)
- MESA composition: "The scores being boosted start from router mass, not activation-based saliency ... It does not combine with REAP-style activation norms." — [arXiv 2609.04453](https://arxiv.org/html/2609.04453)

### Inferences
- Constrained HOPE (inference): partition experts into protected P and free U; with p_P = 0 the objective p^T F p = p_U^T F_UU p_U exactly (the cross terms 2 p_U^T F_UP p_P and p_P^T F_PP p_P vanish). So the protected set changes nothing about the objective's form; it only removes rows/columns and lowers the free budget to n_prune over U. The greedy 1-swap refinement must simply never swap in a protected expert. There is no conflict in the optimisation; the real tension is statistical — protection takes experts whose pairwise F with high-saliency survivors may be low, so the free slice is spent on experts with strong co-activation with the (domain-biased) majority, which is exactly the ballast-collapse mechanism the sibling note flagged for HOPE at 50%.
- The formulation "min p^T F p s.t. per-domain mass loss ≤ τ_d" (MESA's constraint on HOPE's objective) is a quadratic program with linear constraints (each domain's pruned mass is linear in p) — tractable with the same relaxation HOPE already uses. Nobody has published it; it would be the principled replacement for a scalar `protect_frac`.
- Because HOPE's off-diagonal is computed from the same domain-imbalanced token stream, F itself is majority-weighted; protection fixes which experts survive but not the direction of the interaction term. A per-domain-normalised F (EASY-EP/PreMoe-style 1/D weighting of per-domain F_d) is the obvious untested complement.

### Gaps
- No paper reports HOPE (or any interaction-aware criterion) with protected experts; the constrained-QP formulation above is unmeasured.
- HOPE's code location is unconfirmed: the memory note cites github.com/awslabs/hybrid-model-factory, but that README describes hybrid attention/SSM priming with no pruning code (see KQ7).

## KQ5. Does protection fix ballast collapse specifically (general text / MMLU / PopQA under domain-heavy calibration)?

### Takeaway
Partially and only on proxies: GEC's generic-corpus protection lowers WikiText2/C4 PPL by 29–40% vs REAP at 50% retention and lifts commonsense accuracy, but its MMLU is *below* code-calibrated REAP's at 50% on both models; MESA lifts the worst domain (GPQA +18 pts vs REAP) at the price of the best domain; the union guard is reported only on HumanEval+, and no paper reports MMLU/PopQA with vs without protection under domain-heavy calibration.

### Cited Findings
- GEC at 50% retention: W.PPL 16.76 vs REAP 23.77 (−29%) and C.PPL 47.01 vs 61.47 (Qwen); 16.43 vs 27.33 (−40%) and 45.14 vs 61.60 (DeepSeek); Common Avg +0.046/+0.064; MMLU 0.369 vs 0.406 (Qwen) and 0.242 vs 0.287 (DeepSeek), i.e. REAP wins MMLU. — [arXiv 2607.01710 Table 1](https://arxiv.org/html/2607.01710)
- MESA (gpt-oss-20b, 25% pruned): worst-domain GPQA-Diamond 65.48 vs REAP 47.72; AIME'25 −13.34 vs REAP −3.34; general-knowledge was one of the six protected domains but MMLU/MMLU-Pro per-method numbers were not in the retrieved text. — [arXiv 2609.04453](https://arxiv.org/html/2609.04453)
- Half-the-Experts: union guard HumanEval+ 0.829 vs on-policy 0.817 vs plain 0.787 at 25% keep; general-chat PPL under the guard not reported; code-heavy calibration general PPL 5.20 → 12.00 (50% keep) → 30.9 (25% keep). — [arXiv 2607.16721 §5.1, §5.6](https://arxiv.org/pdf/2607.16721)
- EASY-EP math-only calibration on DeepSeek-R1 (50% kept): Agent-OS 3.47 (full 40.51), USMLE 46.43 (92.66), FinanceIQ 58.20 (82.1), GPQA 46.91 (70.91), while AIME24 kept 79.17; mixed-domain restores USMLE 91.20 and GPQA 70.36 but FinanceIQ only 57.95. — [arXiv 2504.06792](https://arxiv.org/html/2504.06792)
- 2610.15578: C4 calibration gives highest MMLU (0.617) vs MATH-calibration 0.585 and private 26-domain corpus 0.611 (gpt-oss-20b, ratio unstated). — [arXiv 2610.15578](https://arxiv.org/html/2610.15578)
- Internal: v2 with `protect_frac = 0` lost ballast; s09_eval by_domain ballast dNLL 1.0027 / top-1 0.579 vs code 0.057 / 0.916; `protect_frac = 0.04` measured at the marginal knee of worst-domain retention vs interaction cost. — [memory: reap-criterion-and-corpus-audit](/home/patrickd/.claude/projects/-home-patrickd/memory/reap-criterion-and-corpus-audit.md); task brief (internal, unpublished)

### Inferences
- The published evidence supports "protection preserves the *modelling* of the protected corpus (PPL, commonsense)" and "minimax protection preserves the worst *benchmark* domain", but not "protection preserves MMLU-style recall". For our ballast metric (held-out general-text dNLL / top-1 agreement) GEC's PPL result is the directly relevant one and it is positive at every ratio; for PopQA/MMLU-type recall nothing published says protection helps, and GEC's MMLU says it may not.
- The MESA AIME −13 pt is the quantified "protection tax": protecting the worst domain shifts loss to the previously best domain. With 7 domains at 60–70% the analogous tax on code/math should be expected and budgeted (extrapolation).

### Gaps
- No paper reports MMLU/PopQA/BBH with and without per-domain protection under a domain-heavy calibration mix; this is the exact experiment our v2-vs-protected comparison performs and it has no external counterpart.
- MESA's MMLU/MMLU-Pro per-method rows were not retrieved (page truncated at 100k chars).

## KQ6. Dynamic / learned alternatives: router-side re-routing vs selection-side protection for minority domains

### Takeaway
Router-side healing recovers more of the general-text loss than any selection-side guard reported: Half-the-Experts' full router + LoRA-r64 self-distillation on 1,863 base-generated prompts brought general-chat PPL from 30.9 to 9.4 (base 5.20) and HumanEval+ 0.787→0.841 at 25% keep, and the translation paper's 10k-example distillation turned a 68.75%-pruned −.082 xCOMET loss into −.038; but both recover the calibration distribution, not uncovered domains, and no study compares router healing against selection-side protection on the same minority domain.

### Cited Findings
- Half-the-Experts §5.7 healing: LoRA rank 64 on attention, linear-attention and shared-expert projections + router matrices trained in full; routed experts frozen; data = base model's answers to 2,047 calibration prompts (1,863 fit), loss on assistant turn; 95.2M trainable (0.86%); general PPL 30.9 → 9.4 (base 5.20, "partial recovery"); code PPL 5.45 → 4.85; HumanEval+ 0.787 → 0.841 (52% of gap), MBPP+ 0.659 → 0.685 (23%); pooled 43 fixed vs 24 lost (McNemar p = 0.027). — [arXiv 2607.16721 §5.7](https://arxiv.org/pdf/2607.16721)
- Translation specialists: full fine-tuning on ~10k synthetic En→{De,Ja,Ru,Es,Zh} pairs generated by the unpruned base (lr 1e-5, 3 epochs, effective batch 16, 4×A6000): 68.75% pruned .859→.904 FLoRes, .734→.786 WMT24++; 75% pruned .902/.789 after distillation (base .942/.830); recovery weaker for Egyptian Arabic and Bengali. — [arXiv 2605.28042v2](https://arxiv.org/html/2605.28042v2)
- UMoE (arXiv 2607.11444, Qwen3-30B-A3B / Qwen3.5-35B-A3B): prune lowest domain-aligned saliency experts, regrow the pool to original size by perturbation-based expansion, then SFT; +3.4 math avg, +6.0 SWE-bench Verified over direct SFT; in-house math 82.81 (direct SFT) → 84.17; effect on non-target domains not described in the abstract. — [arXiv 2607.11444](https://arxiv.org/abs/2607.11444)
- GLM-5.2-504B community release: REAP keep-168 then "Router-KD" distilling only the gate from the unpruned teacher; model card only, no benchmark validation. — [HF 0xSero/GLM-5.2-504B-W4A16](https://huggingface.co/0xSero/GLM-5.2-504B-W4A16)
- GEC and MESA are both static ("does not optimize routing adaptation after pruning"; MESA has no retraining). — [arXiv 2607.01710 Discussion](https://arxiv.org/html/2607.01710); [arXiv 2609.04453](https://arxiv.org/html/2609.04453)
- Internal: FP8 teacher logits for the calibration token set are banked (`teacher_from_cache: true`), so router-only KD is feasible without re-running the 321 GB teacher. — [memory: reap-criterion-and-corpus-audit](/home/patrickd/.claude/projects/-home-patrickd/memory/reap-criterion-and-corpus-audit.md)

### Inferences
- Router healing cannot resurrect a capability whose experts were deleted; it re-routes among survivors. Protection decides whether a ballast expert survives; healing decides whether tokens find it. The two are complementary, and the published recovery magnitudes (general PPL 30.9→9.4 vs guard: unreported) suggest the healing step is the larger lever once some ballast experts survive — which is the argument for keeping `protect_frac > 0` (survival) and adding router-KD on the banked teacher logits (routing).
- All router-side results above distil on the *calibration* distribution; to recover ballast the KD set must contain general text, otherwise healing optimises the same majority distribution that caused the collapse.

### Gaps
- No head-to-head of router healing vs selection-side protection on a held-out minority domain.
- No router-only-KD result with benchmarks (the GLM-5.2 card is unvalidated).

## KQ7. Code and reproducibility (GEC, REAP flags, HOPE, PreMoe, layer streaming on 122 GiB)
